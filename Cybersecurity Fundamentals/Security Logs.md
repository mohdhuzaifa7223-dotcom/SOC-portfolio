# Security Logs - SOC Fundamentals

## What is a Security Log?

A **security log** is a record of events generated by an operating system, application, server, firewall, or network device.

Logs help administrators and SOC analysts understand **what happened, when it happened, who performed the action, where it happened, and whether it was legitimate or malicious.**

Think of logs as a **digital diary** of everything happening on a system.

---

# Why Are Security Logs Important?

Without logs:

* You cannot determine who accessed a system.
* You cannot identify when an attack occurred.
* You cannot investigate security incidents.
* You cannot prove whether data was modified.
* You cannot detect suspicious behavior.

Logs are the primary source of evidence during a cyber investigation.

---

# Information Stored in a Log

A typical log may contain:

* Timestamp (Date & Time)
* Username
* Source IP Address
* Destination IP Address
* Hostname
* Event ID
* Process Name
* File Name
* Status (Success/Failure)
* Severity Level

Example:

```text
Date: 2026-08-07 10:15:42
User: John
Source IP: 192.168.1.15
Action: Login
Status: Success
Event ID: 4624
```

# Types of Security Logs

## 1. Windows Event Logs

Generated by Windows operating systems.

Categories:

* Application
* Security
* System
* Setup
* Forwarded Events

### Security Log

Records:

* User logins
* Failed logins
* Account creation
* Password changes
* Privilege changes

### System Log

Records:

* Driver issues
* Hardware failures
* Windows startup
* Windows shutdown

### Application Log

Records:

* Application crashes
* Software errors
* Program warnings

---

## 2. Linux Logs

Linux stores logs in:

```text
/var/log/
```

Important files:

```text
/var/log/syslog
/var/log/auth.log
/var/log/messages
/var/log/secure
```

Purpose:

* Authentication
* System events
* Service status
* Kernel messages

---

## 3. Firewall Logs

Firewall logs record network traffic entering or leaving a network.

Information stored:

* Source IP
* Destination IP
* Port Number
* Protocol
* Allowed or Blocked
* Timestamp

Example:

```text
192.168.1.20 → 8.8.8.8
Port 443
Allowed
```

SOC analysts use firewall logs to identify suspicious connections and blocked attacks.

---

## 4. Web Server Logs

Generated by web servers such as Apache or Nginx.

Contain:

* Visitor IP
* Requested URL
* Browser
* HTTP Method
* Status Code
* Timestamp

Example:

```text
GET /login HTTP/1.1
Status: 200
```

Useful for detecting:

* SQL Injection
* Directory Traversal
* Brute Force attacks
* Web Scanning

---

## 5. Authentication Logs

Authentication logs record user authentication activities.

Include:

* Login
* Logout
* Failed Login
* Password Reset
* Account Lockout
* MFA Events

These logs help detect unauthorized access attempts.

# Event vs Log vs Alert vs Incident

## Event

An **event** is any activity that occurs on a system.

Example:

```text
User logged in.
```

Every action performed on a computer is an event.

---

## Log

A **log** is the recorded information about an event.

Example:

```text
10:30 AM
John logged in from 192.168.1.20
```

Events become logs after they are recorded.

---

## Alert

An **alert** is generated when a security tool detects suspicious behavior.

Example:

```text
50 failed login attempts within one minute.
```

An alert tells analysts that something requires attention.

---

## Incident

An **incident** is a confirmed security event that requires investigation or response.

Example:

An attacker successfully compromises an administrator account.

Not every alert becomes an incident.

---

# Security Log Levels

Many systems classify logs by severity.

Common levels:

| Level       | Meaning                                       |
| ----------- | --------------------------------------------- |
| Information | Normal activity                               |
| Warning     | Something unusual happened                    |
| Error       | An operation failed                           |
| Critical    | Serious problem requiring immediate attention |

# What Does a SOC Analyst Look For?

Examples of suspicious activity:

* Multiple failed login attempts
* Login at unusual hours
* Login from another country
* Administrator account creation
* New user added to Admin group
* PowerShell execution
* Antivirus disabled
* Unknown process execution
* Large number of file deletions
* USB device connected

Each of these may indicate malicious activity.

---

# Security Investigation Example

Imagine a user reports that their account was hacked.

A SOC analyst might:

1. Check authentication logs.
2. Find failed login attempts.
3. Find the successful login.
4. Identify the source IP.
5. Determine whether the IP is internal or external.
6. Check if the attacker created new accounts.
7. Review process creation logs.
8. Determine what files were accessed.
9. Block the malicious IP if necessary.
10. Document the incident.

---

# Best Practices

* Never delete logs unnecessarily.
* Synchronize system time for accurate timestamps.
* Store logs securely.
* Regularly monitor authentication logs.
* Review critical events daily.
* Send logs to a SIEM for centralized monitoring.

---

# Security Logs and SIEM

Organizations generate millions of logs every day.

Instead of checking each log manually, companies use **SIEM (Security Information and Event Management)** tools.

A SIEM:

* Collects logs from multiple devices.
* Stores them centrally.
* Correlates related events.
* Detects suspicious behavior.
* Generates alerts for SOC analysts.

Popular SIEM tools:

* Splunk
* Microsoft Sentinel
* IBM QRadar
* Elastic Security

# Key Takeaways

* A **log** is a recorded event.
* Logs are essential for detecting, investigating, and responding to security incidents.
* Windows, Linux, firewalls, web servers, and applications all generate logs.

* SIEM tools make it possible to analyze and correlate logs from many systems in one place.
